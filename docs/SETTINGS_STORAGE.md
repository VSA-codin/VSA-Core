# Local settings storage

Status: implemented local nonsecret settings with explicit backup-preserving recovery. No arbitrary-path IPC, automatic migration or profile storage.

The settings object is `{"schemaVersion":1,"compactLayout":false}`. Legacy objects without a version are interpreted as schema 1 without rewriting on read. Explicit Save emits version 1. Both disk and IPC require objects, boolean preferences and strict known/unique fields, including escaped duplicate keys. Arrays/null/numbers, future versions and ambiguous inputs are refused. Unsupported/malformed/repeated version markers also block recovery; manual review is required. Current AppSettings exposes only the preference to Rust callers; serialization adds the version. Missing settings/directories use defaults without creating files.

Reads refuse inappropriate target/directory types and direct symlinks/reparse metadata. Metadata size and actual reads are bounded to 16 KiB (one extra byte detects growth). Writes check serialized size, exclusively create a same-directory temporary file, write/sync/close then rename-replace. Existing temporaries are preserved. Unix new directories/files use 0700/0600, existing directory modes remain untouched; Windows inherits native ACLs. Failed replacement cleans only the owned temporary file. Ordinary save never repairs corrupt/unsupported settings.

Explicit two-step recovery exclusively creates `settings.json.corrupt.bak`, writes exact original bytes and flushes them before resetting. Existing backups are never overwritten. Rereading after backup detects ordinary changes/missing originals before reset; backup survives refusal. Failed backup/flush leaves original data in place; partial backup may require manual handling. A corruption backup may contain arbitrary manually supplied bytes and is never included in support output. Unavailable/oversized/unsafe files do not offer automatic recovery.

The process-local mutex serializes bounded operations in one instance. It is not a cross-process lock or atomic compare-and-swap. Direct-link checks do not resolve every ancestor symlink (Linux), parent junction/reparse point (Windows), hard link or same-user check/use race. Native ACL correctness and special/network filesystems need review. A same-user attacker can still tamper with files/process memory. No OS sandbox or secret protection is claimed.

File sync/rename does not guarantee parent-directory power-loss durability; directories are not synced, platform replacement behavior and sudden media loss remain limits. Deterministic tests cover successful Linux/Windows ordinary replacement through CI, collisions, corruption backups, bounded input, future/duplicate schema refusal, Unicode paths and failure preservation. Windows reparse/ACL races, disk-full/flush failures, actual power loss and concurrent processes require manual tests.

Diagnostics report read state, never inferred write access. Only a successful attempted Save proves that specific write succeeded; it does not promise future write access. Future migrations must be version-specific, backup-first, explicit and tested; older binaries must never silently reset newer data. See [Windows uninstall persistence](WINDOWS_PACKAGING.md) and [profile boundary](FOUNDATION_CONTRACTS.md#profiles-and-encrypted-portable-storage).
